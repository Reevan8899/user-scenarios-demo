# Пользовательские сценарии

**Проект** — Менеджер заметок  
**Версия** — 1.0  
**Дата** — 8 ноября 2026 г.

Каждый сценарий описывает одну пользовательскую цель. В основном потоке приведён штатный порядок действий. Альтернативные потоки указывают шаг, на котором меняется результат. [Связанные требования из практической № 5](https://github.com/Reevan8899/requirements-demo/blob/main/docs/srs.md)

## SC-001

**Название** — Добавление заметки  
**Актор** — Владелец заметок  
**Предусловие** — Приложение запущено. Для записи доступен каталог хранилища.  
**Триггер** — Пользователь вызывает `note add`.

### Основной поток

1. Система принимает заголовок из аргумента `--title` или запрашивает его.
2. Система очищает пробелы по краям и проверяет длину заголовка от 1 до 100 символов.
3. Система принимает тело из `--body` или запрашивает его.
4. Система очищает пробелы по краям и проверяет длину тела от 1 до 10 000 символов.
5. Система присваивает заметке UUID, дату создания и такую же дату изменения.
6. Система атомарно сохраняет заметку вместе с существующими записями.
7. Система сообщает об успехе и показывает ID.

### Альтернативные потоки

- **2a.** Пустой или слишком длинный заголовок вызывает русскоязычную ошибку. В интерактивном режиме система снова запрашивает заголовок.
- **4a.** Пустое или слишком длинное тело вызывает ошибку. Запись не создаётся.
- **6a.** При ошибке чтения или записи система сообщает о проблеме. Сохранённые данные остаются доступными в прежнем виде, если сбой произошёл до замены файла.
- **1a / 3a.** Завершение ввода отменяет операцию.

### Постусловие

При успехе новая заметка сохранена и доступна по выданному ID.

**Связанные требования** — FR-001, UR-001, NFR-002, NFR-004.  
**Модуль** — [`src/scenarios/add_note.py`](../src/scenarios/add_note.py)  
**Тесты** — [`tests/test_add_note.py`](../tests/test_add_note.py)

## SC-002

**Название** — Просмотр списка заметок  
**Актор** — Владелец заметок  
**Предусловие** — Приложение запущено. Для основного потока в хранилище есть заметки.  
**Триггер** — Пользователь вызывает `note list`.

### Основной поток

1. Система загружает все заметки.
2. Система упорядочивает их по дате создания от новых к старым.
3. Система выводит таблицу с ID, заголовком и датой создания.

### Альтернативные потоки

- **1a.** Пустое или ещё не созданное хранилище даёт сообщение «Заметок пока нет».
- **1b.** Ошибка чтения приводит к сообщению с подсказкой проверить файл.

### Постусловие

Владелец увидел список или причину, по которой он недоступен. Записи не меняются.

**Связанные требования** — FR-002, UR-002.  
**Модуль** — [`src/scenarios/list_notes.py`](../src/scenarios/list_notes.py)  
**Тесты** — [`tests/test_list_notes.py`](../tests/test_list_notes.py)

## SC-003

**Название** — Поиск заметок  
**Актор** — Владелец заметок  
**Предусловие** — Пользователь знает часть заголовка или текста.  
**Триггер** — Пользователь вызывает `note search --query "слово"`.

### Основной поток

1. Система принимает и проверяет запрос.
2. Система загружает заметки.
3. Система сравнивает запрос с заголовками и текстами без учёта регистра.
4. Система выводит совпадения с ID и заголовками.

### Альтернативные потоки

- **1a.** Пустой или пробельный запрос вызывает подсказку ввести слово.
- **2a.** Ошибка чтения выводится на русском языке.
- **4a.** При отсутствии совпадений система сообщает «Ничего не найдено».

### Постусловие

Владелец получил результаты поиска. Записи не меняются.

**Связанные требования** — FR-003, UR-003.  
**Модуль** — [`src/scenarios/search_notes.py`](../src/scenarios/search_notes.py)  
**Тесты** — [`tests/test_search_notes.py`](../tests/test_search_notes.py)

## SC-004

**Название** — Редактирование заметки  
**Актор** — Владелец заметок  
**Предусловие** — Владелец знает ID существующей заметки.  
**Триггер** — Пользователь вызывает `note edit ID`.

### Основной поток

1. Система находит заметку по ID.
2. Система принимает новые поля из `--title` и `--body` или запрашивает их.
3. Система проверяет введённые значения по правилам SC-001 и сохраняет пропущенные поля.
4. Система обновляет дату изменения, сохраняя ID и дату создания.
5. Система атомарно записывает новую версию и подтверждает изменение.

### Альтернативные потоки

- **1a.** Неизвестный ID вызывает подсказку проверить список заметок.
- **2a.** Нажатие Enter при запросе поля сохраняет прежнее значение. Если пропущены оба поля, запись и дата изменения остаются прежними.
- **2b.** Завершение ввода отменяет операцию.
- **3a.** Некорректное введённое значение вызывает сообщение об ошибке, запись не меняется.
- **5a.** Если запись прерывается до замены файла, остаётся прежняя версия.

### Постусловие

При успехе изменены только указанные поля, сохранены идентификатор и дата создания.

**Связанные требования** — FR-004, UR-004, NFR-002.  
**Модуль** — [`src/scenarios/edit_note.py`](../src/scenarios/edit_note.py)  
**Тесты** — [`tests/test_edit_note.py`](../tests/test_edit_note.py)

## SC-005

**Название** — Удаление заметки  
**Актор** — Владелец заметок  
**Предусловие** — Владелец знает ID существующей заметки.  
**Триггер** — Пользователь вызывает `note delete ID`.

### Основной поток

1. Система находит заметку по ID.
2. Система показывает заголовок и запрашивает подтверждение.
3. Владелец отвечает «да».
4. Система удаляет запись и атомарно сохраняет обновлённое хранилище.
5. Система подтверждает удаление.

### Альтернативные потоки

- **1a.** Неизвестный ID вызывает подсказку проверить список заметок.
- **3a.** Отказ или завершение ввода отменяет операцию без изменений.
- **4a.** Ошибка записи до атомарной замены оставляет прежний файл.

### Постусловие

После подтверждённого удаления выбранная заметка отсутствует, остальные записи сохранены.

**Связанные требования** — FR-005, UR-005, NFR-002.  
**Модуль** — [`src/scenarios/delete_note.py`](../src/scenarios/delete_note.py)  
**Тесты** — [`tests/test_delete_note.py`](../tests/test_delete_note.py)
